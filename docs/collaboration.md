# 협업 규칙 (T7 합의)

**팀**: A 권순원(작품·가져오기) · B 엄장헌(기록·수집) — 도메인 수직 분담, 바이브 코딩.

## 브랜치·PR

- 브랜치: `main`(항상 배포 가능) + `feat/a-이슈번호-설명` / `feat/b-이슈번호-설명`
- 모든 변경은 PR로 `main`에 머지. 직접 푸시 금지
- **24시간 내 승인 원칙** — 상대 PR을 하루 안에 검수한다

## PR 검수 방법 (코드를 읽지 않는다)

1. PR의 **Vercel 프리뷰 배포 URL**을 연다
2. 해당 Linear 이슈의 **완료 조건을 직접 눌러서** 확인한다
3. **회귀 스모크 CI가 초록**인지 확인한다 (빨강이면 머지 금지 — 원인 수정 요청)
4. 둘 다 통과면 Approve → Merge
- 프리뷰에서 확인 불가능한 완료 조건을 발견하면 → 그 이슈의 완료 조건을 '화면에서 확인 가능한 행동'으로 다시 쓴다
- 인증·권한이 걸린 이슈(T25 등)는 **계정 2개 교차 확인**(타인 데이터 접근 불가) 필수

## 머지 데이 (매주 금요일, 30분)

1. 서로의 도메인 화면을 완료 조건 기준으로 교차 검수 (엣지 입력·연타·뒤로가기 포함)
2. 스모크 전체 초록 확인
3. (소프트 런칭 후) 프로덕션 DB 수동 백업 — Supabase 대시보드 → Database → Backups 또는 pg_dump. Supabase Free는 자동 백업이 없다
4. 다음 주 이슈 순서 확인

## 원칙

- **배포된 상태만 진도로 인정** — "로컬에서는 돼요"는 진도가 아니다
- **서로 기다리면 계획 위반 신호** — 시드 데이터(T9)·계약 문서(T8) 덕에 두 트랙은 병렬이다. 기다리게 되면 즉시 논의
- 스타일 논쟁 금지 — 린터·포매터 기본값에 위임
- 스키마·계약 변경: 제안 → 15분 합의 → `docs/contract.md` 갱신 → 마이그레이션 파일 → 사람이 적용
